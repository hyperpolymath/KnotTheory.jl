== Verification Architecture

=== Core Types and Representations

KnotTheory.jl implements knot theory using mathematically precise representations:

**Crossing Type:**
- `arcs::NTuple{4, Int}`: Under-strand enters at arc `a`, exits at `c`; over-strand enters at `d`, exits at `b`
- `sign::Int`: Crossing sign (+1 or -1)
- Follows KnotAtlas PD (Planar Diagram) convention

**PlanarDiagram Type:**
- Aggregates `Vector{Crossing}` to represent a knot diagram
- Supports multi-component links
- Can be converted to/from various representations

**Knot Type:**
- Wraps `PlanarDiagram` with metadata
- Represents a single-component knot

**Link Type:**
- Generalizes `Knot` to multi-component structures
- `components::Vector{Vector{Int}}` field tracks component connectivity

**DTCode Type:**
- Dowker-Thistlethwaite code representation
- Efficient for storage and lookup

**Polynomial Representation:** All polynomials use `Polynomials.jl` for representation
and arithmetic.

**Test Verification:**
- Alexander polynomial of trefoil: `t^-1 - 1 + t` — ✅ PASS
- Jones polynomial of trefoil: `-t^-4 + t^-3 + t^-1` — ✅ PASS

**Performance Caveat:** HOMFLY polynomial computation is exponential in crossing
number. For knots beyond ~12 crossings, computation is impractical without
specialized simplification. The package does not implement Kauffman bracket
shortcuts for performance.

=== Planned Formal Proofs

Integration with Axiom.jl would enable:

[source,julia]
----
using Axiom
using KnotTheory

# Planar diagram properties
@prove forall(pd::PlanarDiagram) do crossing_number(pd) >= 0 end
@prove forall(pd::PlanarDiagram) do crossing_number(pd) == length(pd.crossings) end

# Polynomial invariants
@prove forall(k::Knot) do 
    alexander_polynomial(k) == alexander_polynomial(simplify_pd(k)) end
@prove forall(k::Knot) do 
    jones_polynomial(k) == jones_polynomial(simplify_pd(k)) end

# Reidemeister move properties
@prove forall(pd::PlanarDiagram) do 
    crossing_number(r1_simplify(pd)) <= crossing_number(pd) end
@prove forall(pd::PlanarDiagram) do 
    crossing_number(r2_simplify(pd)) <= crossing_number(pd) end
@prove forall(pd::PlanarDiagram) do 
    crossing_number(r3_simplify(pd)) <= crossing_number(pd) end

# Simplification convergence
@prove forall(pd::PlanarDiagram) do 
    simplify_pd(simplify_pd(pd)) == simplify_pd(pd) end  # Idempotence

# Knot equivalence
@prove forall(k::Knot) do 
    is_unknot(k) == (crossing_number(simplify_pd(k)) == 0) end

# Braid conversion roundtrip
@prove forall(bw) do 
    to_braid_word(from_braid_word(bw)) == bw end  # For valid braids
----

== Honest Caveats

From EXPLAINME.adoc:

. Package is at 95% completion (TOPOLOGY.md). The one remaining gap is the
  HOMFLY polynomial performance optimisation for large knots.

. The knot table (`knot_table`) contains a small built-in set of classical
  knot atlas entries.

. PD code construction for arbitrary user-defined knots requires manual arc
  labelling following the KnotAtlas convention, which is non-trivial for
  non-experts. No GUI diagram editor is provided.

. AcceleratorGate dispatch is hooked via `backends/abstract.jl`; GPU paths
  are not yet operative.

== Implementation Details

The package is implemented in a single file `src/KnotTheory.jl` (~1200 lines),
with `src/backends/abstract.jl` as the only include. This monolithic structure
makes it easy to understand and verify the complete implementation.
